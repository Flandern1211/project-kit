# Contributing

Every non-trivial change starts from a task or bug record under `docs/work/`.
Use a short-lived branch named `codex/<record-id>-<slug>` and keep unrelated
changes out of the branch.

Before opening a pull request:

1. link the task or bug record;
2. update the record with changed files and verification evidence;
3. run `pgk check` and the project test suite;
4. document unresolved risks and the rollback or follow-up action;
5. ask for review before merging or publishing.

The repository Markdown record is authoritative. GitHub Issues and pull
requests are discussion and review links, not a second copy of the complete
requirements or design.
