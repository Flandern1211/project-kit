# ADR-0004 后续功能范围收口

## Purpose

记录用户对 Project Governance Kit 后续功能范围的最新确认，避免把需求文档中的
“当前不实现”或“延期”误解为必须完成的产品路线图。

## Scope

本决策只调整未来路线图，不改变 v0.1、v0.2 已实现行为，不授权本次实现任何新功能，
也不改变现有 Git 受保护动作边界。

## Acceptance

用户于 2026-09-16 明确确认，后续只保留以下两个功能扩展：

1. 并行 Agent 协作安全与 worktree 管理，包括任务、分支、worktree、文件范围、
   冲突预检、状态汇总和生命周期检查；不包含自动合并。
2. 受授权的本地自动 commit，包括任务级明确授权、提交前验证、敏感文件检查、
   TASK/BUG 关联和提交后 clean-tree 检查；授权 commit 不自动授权 push、PR、merge、
   tag 或 release。

以下能力不再作为延期功能或候选路线图，而是明确的产品非目标：

- Web 管理后台和托管式协作服务；
- 核心 Kit 的模型提供商调用；
- PDF、Word、Excel、图片等复杂格式自动转换；
- 文档语义总结、自动拆分、自动合并或自动改写；
- Git 历史自动清理和远程仓库权限修改；
- 自动治理等级评估；
- 通用 Issue/PR 或其他外部平台集成；
- 公开副本自动导出；
- 自动 push、PR、merge、tag 或 release。

手工使用 GitHub/GitLab Issue、PR 或独立公开仓库仍然允许，但不由 Kit 自动化。
现有 `team-private`、`hybrid` 和 `public` 可见性模式继续保留；公开内容由用户审查和
发布，不新增自动导出能力。

## Evidence

2026-09-16 用户在现状与路线图讨论后确认：“这两个作为后续的功能扩展，剩下都可以
删掉了”。“这两个”指并行 Agent 协作安全/worktree 管理和受授权的本地自动 commit。

## Changes

- 本 ADR 在未来路线图范围上取代 ADR-0002 的“后续可选扩展”概括；
- ADR-0003 的可见性决策继续有效，但其中公开副本导出、仓库拆分、历史清理和远程
  权限修改不再属于延期路线图；
- 同步当前需求、设计、状态和用户文档，将未来能力分为明确 planned 和 non-goal；
- 不修改 CLI、配置格式、版本号或已验证功能。

## Blockers

无。两个后续扩展尚未进入设计或实现，开始前仍需分别建立被接受的需求、设计和任务。

## Next action

保持当前实现稳定；只有用户决定启动其中一个扩展时，才创建对应需求和设计记录。
