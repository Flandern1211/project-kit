# Agent-first 项目启动入口需求

## 1. 目标

用户应当可以只与 Codex 等本地开发 Agent 对话，由 Agent 调用 Project Governance
Kit 完成新项目初始化、已有项目接入预检、治理记录维护和需求确认门禁。用户不需要先
手工执行 `pgk init`；CLI 继续作为 Agent 使用的确定性执行层和高级用户备用入口。

## 2. 核心交互

### 2.1 新项目

当用户要求“使用 PGK 创建/开始/建设一个新项目”时，Agent：

1. 确认目标目录、项目名称和必要的可见性选择；未指定 profile 和协作模式时使用 Kit
   默认值；
2. 检查 `pgk` 是否可用，并预览初始化结果；
3. 仅创建缺失的治理骨架，不覆盖已有内容；
4. 读取生成的 `AGENTS.md`、`docs/INDEX.md`、`docs/project-structure.md` 和
   `docs/STATUS.md`；
5. 根据用户已经表达的目标创建 `draft` 需求记录；
6. 向用户总结需求并请求确认；需求成为 `accepted` 前不得开始设计或业务实现。

用户要求使用 PGK 建立新项目，视为授权在目标目录创建缺失的治理文件，但不自动授权
`git init`、commit、push、merge、删除或任何远程操作。

### 2.2 已有项目

当目标目录已包含代码、文档或 Git 历史但尚未接入 PGK 时，Agent 必须先运行只读的
`pgk adopt` 和 `pgk doctor`，向用户展示候选映射、缺失文件、Git 状态、敏感项和建议
方案。用户确认前不得运行 supplement、迁移 apply 或覆盖现有文件。

### 2.3 已治理项目

当目标项目已经包含 PGK 配置和治理入口时，Agent 不重复初始化。它读取项目指令、状态
和当前记录，然后按现有任务或用户的新请求继续工作。

## 3. 触发和非触发

以下意图应触发 Agent-first 入口：

- 使用 PGK 创建、启动、建设或治理一个项目；
- 让 Agent 负责初始化并开始需求讨论；
- 把一个已有项目安全接入 Project Governance Kit；
- 在一个已经治理的项目中恢复或继续工作。

仅询问 PGK 的概念、比较工具、阅读文档或请求普通代码修改，不应自动初始化或接入项目。

## 4. 输出和暂停点

每次入口运行必须向用户说明：

- 识别到的新项目、已有项目或已治理项目状态；
- 已执行的只读检查和本地写入；
- 当前治理阶段和唯一下一步；
- 需要用户确认的需求、接入方案或受保护动作。

新项目入口的正常暂停点是需求确认；已有项目入口的正常暂停点是接入方案确认。

## 5. 边界

- 入口以 Codex Skill 形式封装现有本地 CLI，不新增 Web 后台、模型调用或远程服务；
- Skill 不绕过目标仓库的 `AGENTS.md`、需求状态和授权规则；
- `pgk` 不可用时，Agent报告安装阻塞和可执行的本地安装步骤，不伪造成功；
- 不自动接受需求，不自动生成业务设计结论，不自动执行 Git 受保护动作；
- 这是一层 Agent 使用体验，不是 ADR-0004 之外的第三项核心运行功能。

## 6. 验收标准

- AC-01：新项目对话能够驱动预览、初始化、必读文件加载和 draft 需求创建；
- AC-02：需求确认前不会创建设计、任务或业务代码；
- AC-03：已有项目首先执行只读 adopt/doctor，确认前不写入；
- AC-04：已治理项目不会被重复初始化；
- AC-05：咨询类或普通开发请求不会误触发项目初始化；
- AC-06：Skill 明确区分治理文件写入授权和 Git/远程受保护动作授权；
- AC-07：缺少 `pgk`、路径不明确或检查失败时提供准确阻塞信息；
- AC-08：至少通过新项目、已有项目和已治理项目三类对照测试。

## 7. 用户确认

用户于 2026-09-16 确认采用“用户只与 Agent 对话，Agent 操作 Kit”的方向，并要求按此
方向扩展或改造。
