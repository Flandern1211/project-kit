# Project Governance Kit v0.1 需求规格

> 本文是[英文原文](2026-09-02-project-governance-kit-v0.1-requirements.md)的中文版本，需求编号和约束保持一致。

- 状态：已确认，用于初始实现
- 版本：0.1
- 日期：2026-09-02

## 1. 目标

提供一套面向 Agent、同时方便人阅读的工具包，使软件项目能够在不同 Agent
会话、模型和贡献者之间恢复。工具包通过统一持久记录、Git 引用、验证证据
和交接信息来实现这一目标。

## 2. 范围

第一版面向本地 Git 仓库，生成版本化 Markdown 文件和小型项目配置文件，且
适用于使用不同编程语言的项目。工具包本身使用 Python 3.11+ 实现，运行时
除标准库外不引入其他依赖。

## 3. 功能需求

### FR-01 初始化

`pgk init` 应根据选定的 profile 只创建缺失的治理文件，报告被跳过的已有
文件，并且绝不覆盖已有的指令文件或项目文档。

### FR-02 接入和检查

`pgk adopt` 和 `pgk doctor` 默认应以只读方式检查已有仓库，并报告缺失的治理
产物以及可以映射的既有结构。

### FR-03 记录创建

`pgk new` 应根据模板创建 requirement、design、decision、task、bug 和
verification 记录。每条记录都应包含唯一 ID、文档类型、生命周期状态、日期
以及关联记录链接。

### FR-04 验证

`pgk check` 应检查受支持的 frontmatter、重复 ID、允许的状态、本地 Markdown
链接、必需的基线文件和基本仓库状态。发现错误时返回非零退出码，并支持稳定
的 JSON 输出。

### FR-05 交接

`pgk handoff` 应更新已有任务记录的交接区域，写入当前分支、提交、工作区状态、
验证状态、阻塞项和一个明确提供的下一步动作。它不应捕获密钥或完整终端输出。

### FR-06 Git 上下文

工具包应在不执行 commit、push、merge、reset 或删除操作的情况下，读取分支、
HEAD、工作区状态和最近提交。

### FR-07 自验证

工具包仓库本身应使用自己的需求、设计、任务、测试、验收和交接记录，并能够
用自身的检查命令完成自验证。

## 4. 非功能需求

- 对相同仓库状态产生确定性输出；
- 默认提供人类可读输出，并提供机器可读的 `--json` 输出；
- 所有可写命令提供明确的 `--dry-run` 预览；
- 出错时安全退出，并给出可执行的修复提示；
- 支持 Windows、macOS 和 Linux；
- 核心 CLI 不保存凭据，也不产生模型提供商流量；
- 生成的文件是普通项目文件，不依赖中心化服务。

## 5. v0.1 不包含

- 自动修改 GitHub、GitLab 或 Plane API；
- 自动 commit、push、merge 或 release；
- Web 管理后台或托管式协作服务；
- 运行日志采集和存储；
- 对需求或架构进行语义审批；
- 代码生成和模型提供商调用；
- 项目专用的业务模板。

## 6. 验收标准

- AC-01：空 fixture 仓库可以无错误完成初始化；
- AC-02：已有仓库可以在不改文件的情况下完成检查；
- AC-03：所有 v0.1 记录类型都可以生成有效 metadata；
- AC-04：检查器可以发现重复 ID、非法状态和断开的本地链接；
- AC-05：交接输出包含 Git 状态和提供的下一步动作；
- AC-06：`--json` 输出可以解析，且格式稳定，适合 Agent 调用；
- AC-07：工具包可以运行自身的检查和测试；
- AC-08：可以检查 TouzhiAgent 这一外部试验项目，且不会把基金业务规则导入工具包。
